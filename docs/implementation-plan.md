# Implementation Plan — There and Back

Поэтапный план реализации приложения от пустого репозитория до релиза в сторы.
Не заменяет [`CLAUDE.md`](../CLAUDE.md) — это авторитетный источник по стеку,
архитектуре и продуктовым решениям; этот файл лишь раскладывает его в
последовательность фаз с ключевыми модулями и критериями готовности каждой.

Ссылки `§N` — разделы `CLAUDE.md`.

---

## Milestone M1 — Foundation (Phase 0–3)

Ничего пользовательского — фундамент, на котором стоит всё остальное. Чистый
Dart и скаффолдинг, без health-данных и сетевых вызовов.

### Phase 0 — Repo & tooling bootstrap

Превратить спеку в работающее (пустое) приложение: `flutter create`,
feature-first дерево из §4, все зависимости из таблицы стека (§3), CI,
прогоняющий чек-лист из §10 на каждый пуш.

- **Модули:** `lib/app/`, `lib/core/`, `lib/design/`, `lib/features/{journey,steps,quest_map,achievements,friends,profile}/`, `analysis_options.yaml`, `.github/workflows/ci.yaml`
- **Готово, когда:** `flutter analyze` чист на пустом скаффолде; `build_runner build` проходит без целей генерации; CI блокирует мердж при падении analyze/test.

### Phase 1 — Design system & app shell

`lib/design/` по §9 — почти чёрный фон, тёплое золото, один антиквенный serif
для заголовков и цифр. `go_router` на пять вкладок (Путь · Карта · Трофеи ·
Друзья · Настройки) как заглушки. l10n-скаффолдинг (ru/en) — сразу, не потом:
§11 запрещает хардкод строк в UI с первого дня.

- **Модули:** `lib/design/colors.dart`, `typography.dart`; `lib/app/router.dart`, `theme.dart`; `lib/l10n/app_ru.arb`, `app_en.arb`
- **Готово, когда:** все пять вкладок открываются без тупиков; на каждую — widget-тест на рендер; ноль строковых литералов в `build()`.
- **Зависит от:** Phase 0

### Phase 2 — Domain layer

Все сущности из §5 чистым Dart — `Journey`, `Segment`, `NarrativeBeat`,
`Landmark`, `Progress`, `StepSample`, `UserProfile`, `Friendship`,
`Achievement` — плюс четыре расчёта, на которых держится доверие к
приложению: шаги → метры через `stride.dart` (дефолт 0.75 м, ручное значение
приоритетнее, платформенная `DISTANCE_WALKING_RUNNING` приоритетнее шагов,
прогресс никогда не убывает), день квеста/темп/ETA (§5.3), форматтер чисел
(§5.4), маппинг метры ↔ точка на карте по полилинии (§6.2). Ни одного
импорта `package:flutter`, Firebase или `health` в этом слое — правило §4 и
§13.

- **Модули:** `features/journey/domain/stride.dart`, `pace_eta.dart`; `features/quest_map/domain/route_mapping.dart`; `features/achievements/domain/evaluator.dart`; `core/formatters.dart`
- **Готово, когда:** unit-тесты зелёные на весь список из §12 (домен); маппинг маршрута протестирован на границах 0 м и полной длины; слой компилируется без Flutter SDK импортов.
- **Зависит от:** Phase 0

### Phase 3 — Local data layer (drift)

drift-схема, зеркалящая доменные сущности, с `lastSyncedAt` и ключом
идемпотентности `(userId, journeyId, intervalStart)` из §5.2 — это то, что
делает офлайн-first (§8) безопасным. Репозитории в `data/`; Firestore DTO и
доменные сущности — разные типы, маппинг явный.

- **Модули:** `data/drift/schema.dart`, `database.dart`; `features/journey/data/progress_repository.dart`; `features/steps/data/step_sample_repository.dart`
- **Готово, когда:** тест миграции drift-схемы; повторный синк того же интервала не удваивает прогресс; интервалы с темпом > 250 шагов/мин помечаются флагом, не отбрасываются молча (§5.2).
- **Зависит от:** Phase 2

## Milestone M2 — Core Experience (Phase 4–7)

Приложение становится играбельным офлайн на захардкоженном/сид-квесте.
Самый крупный milestone — вкладка «Путь» здесь центральная.

### Phase 4 — Steps integration

Единый интерфейс `StepCountingService` над Health Connect (Android, через
пакет `health`) и, **временно**, Core Motion/`CMPedometer` вместо HealthKit
на iOS (§3, §14 — HealthKit требует платный Apple Developer Program).
Разрешение запрашивается только при старте квеста — не на запуске
приложения — с экраном-объяснением (§7). Отсутствие Health Connect на
устройстве обрабатывается диплинком в Play Store. Отказ в разрешении — не
тупик: карточка «нет данных о шагах» + кнопка перезапроса.

- **Модули:** `features/steps/data/step_counting_service.dart` (интерфейс + общий mixin), `android_step_counting_service.dart`, `ios_step_counting_service.dart`; `features/steps/presentation/permission_gate.dart`
- **Готово, когда:** integration_test проходит хотя бы на одной платформе; widget-тест покрывает путь с отказом в разрешении; запись в Firestore батчами, не на каждый тик сенсора (§8).
- **Зависит от:** Phase 3

### Phase 5 — «Путь» tab — Flame-сцена

Центральный экран (§6.1): свободно скроллящаяся горизонтальная
`ParallaxComponent`-лента вдоль всего маршрута, слои с разными
`velocityMultiplier`, небо — процедурный градиент по реальному времени
суток игрока со звёздным слоем. Якоря `< Start` и `You >` анимируются, не
прыгают. Фигурка путника существует только в позиции `You`; новые шаги
интерполируются 800–1200 мс, камера следует, если игрок уже смотрит туда.
По завершении: закрываемый экран награды, сцена замирает на точке B,
следующий квест выбирается вручную в Настройках — шаги между завершением и
выбором не теряются, копятся буфером (§6.1).

- **Модули:** `features/journey/presentation/journey_scene.dart`, `sky_gradient.dart`, `traveler_component.dart`
- **Готово, когда:** смещение параллакса линейно позиции скролла (§12); игровой цикл останавливается на невидимой вкладке; стабильные 60 fps на среднем железе.
- **Зависит от:** Phase 1, Phase 4

### Phase 6 — «Карта» tab — Quest Stats

Один заранее нарисованный `map.webp` на квест с пан/зумом через
`InteractiveViewer` — полностью офлайн, без тайлового сервера (§6.2).
Полилиния маршрута и хотспоты ориентиров — из `map.json` в нормализованных
координатах `(0..1, 0..1)`; пройденный/непройденный участки стилизованы
по-разному, недостигнутые ориентиры приглушены. Пины друзей поверх карты +
список под ней (имя, цвет пина, дельта).

- **Модули:** `features/quest_map/presentation/map_view.dart`, `friend_pins.dart`
- **Готово, когда:** маппинг метры ↔ точка на карте протестирован (общий с Phase 2); пан/зум работает без сети; widget-тест на рендер пинов и списка друзей.
- **Зависит от:** Phase 2

### Phase 7 — «Трофеи» tab

Сетка, полностью управляемая evaluator'ом из Phase 2 — условия достижений
это данные в конфиге, проверяемые одной чистой функцией, без захардкоженной
логики на каждое достижение в виджете (§6.3). Полученные — золотом,
неполученные — силуэтом с прогресс-подписью («осталось 40 км»).

- **Модули:** `features/achievements/presentation/achievement_grid.dart`, `data/achievement_config.dart`
- **Готово, когда:** widget-тест на состояния locked/unlocked; новое достижение добавляется правкой только конфига.
- **Зависит от:** Phase 2

## Milestone M3 — Social & Backend (Phase 8–9)

Приложение перестаёт быть single-player. Всё здесь касается Firestore
Security Rules — §13 требует сначала план, потом код.

### Phase 8 — Firebase: Auth, Firestore, Friends

Схема из §8: `users/{uid}`, `users/{uid}/progress/{journeyId}`,
`friendships/{pairId}`, read-only каталог `journeys/{journeyId}`. Заявка в
друзья требует взаимного подтверждения, до `accepted` прогресс не виден.
Цвет пина друга назначается один раз и стабилен между картой и таблицей
(§6.4). Пользователь может скрыть прогресс от конкретного друга (§7).
Security Rules обязаны разрешать чтение чужого прогресса только при
`accepted`-дружбе.

- **Модули:** `data/firestore/friendship_repository.dart`; `features/friends/presentation/challengers_tab.dart`; `firestore.rules`
- **Готово, когда:** тесты Security Rules в эмуляторе зелёные (§12); заявки до `accepted` не отдают данных прогресса; сырые health-данные и геолокация никогда не попадают в Firestore (§7, §13).
- **Зависит от:** Phase 3, Phase 6

### Phase 9 — Cloud Functions & push

Серверные триггеры на два момента, ради которых стоит прерывать
пользователя: друг обогнал, друг дошёл до ориентира. Подключены к FCM,
агрегация — не на клиенте.

- **Модули:** `functions/src/onProgressUpdate.ts`; `features/friends/data/notification_repository.dart`
- **Готово, когда:** функции покрыты unit-тестами на эмуляторе; ручная запись прогресса триггерит ожидаемый пуш в эмуляторе.
- **Зависит от:** Phase 8

### Standalone — постоянное отображение на экране блокировки (Android)

Не привязана к номеру фазы выше — CLAUDE.md §7 описывает её отдельно от
пушей, и ни один Phase 4–10 её не покрывает; сделана как отдельное
плановое изменение по правилу §13 (новая зависимость + разрешения → сначала
план). Закрывает заодно и открытый вопрос §7/§14 "механизм фонового
синка" — для Android; iOS-механизм остаётся открытым.

Android-only: постоянное уведомление (шторка + экран блокировки) через
`flutter_local_notifications`, обновляется по прогрессу как из foreground-
синка, так и из периодической фоновой задачи `workmanager` (15 минут — пол
`WorkManager`). iOS (Live Activity, нативный Widget Extension на Swift) —
намеренно отложена: свой план и PR, см. документ ниже.

- **Модули:** `features/journey/domain/lock_screen_snapshot.dart`; `features/journey/data/lock_screen_channel.dart`, `android_lock_screen_channel.dart`; `features/steps/data/steps_sync_engine.dart` (общий алгоритм синка, вынесен из `StepsSync.sync()`), `android_background_sync.dart`; `features/journey/presentation/lock_screen_controller.dart`; `features/profile/presentation/settings_tab.dart` (тумблер)
- **Готово, когда:** тумблер в Настройках включает уведомление только после двух разрешений (`POST_NOTIFICATIONS`, Health Connect background-read); уведомление переживает закрытие приложения и обновляется фоновой задачей; выключение тумблера отменяет и задачу, и уведомление; `positionLabel` — честный плейсхолдер до Phase 6/11.
- **Подробности:** [`docs/screens/lock-screen.md`](screens/lock-screen.md)
- **Зависит от:** Phase 3 (drift), Phase 4 (steps sync)

## Milestone M4 — Content & Release (Phase 10–12)

Замыкание цикла, ради которого приложение строилось: выбрать следующий
квест, пройти реальный от начала до конца, отгрузить.

### Phase 10 — «Настройки» tab

Профиль, ручная длина шага (переопределяет дефолт 0.75 м из §5.1), единицы
км/мили, приватность, точка перезапроса разрешений, смена языка, «Смена
квеста» — здесь же буфер шагов завершённого квеста зачисляется в новый
(§6.1, пункт 4).

- **Модули:** `features/profile/presentation/settings_tab.dart`; `features/journey/presentation/quest_picker.dart`
- **Готово, когда:** каждая мутация проходит через репозиторий, не через локальный стейт; смена квеста корректно зачисляет буфер шагов.
- **Зависит от:** Phase 3, Phase 5

### Phase 11 — Content pipeline — «Одиссея»

Довести существующий черновик — `assets/journeys/odyssey-ithaca/locations.json`,
120 ориентиров на 15 сегментах от Трои до Итаки — до играбельного квеста:
реальные пиксельные координаты в `map.json`, когда появится `map.webp`,
редакторская/переводческая правка нарратива на `ru`, слои параллакса по
биомам (руины у моря, побережье налётчиков, штормовое море, дюны сна,
вулканический утёс, парящий остров, фьорд великанов, зачарованный лес,
подземное царство, …), каждый слой бесшовный на горизонтальном зацикливании
(§9.1). **Уже начато** — JSON-черновик существует, фаза его достраивает.

- **Модули:** `assets/journeys/odyssey-ithaca/locations.json`, `map.json`, `map.webp`, `segments/`; `l10n/app_ru.arb` (строки нарратива)
- **Готово, когда:** один квест, Троя → Итака, полностью играбелен на реальных ассетах; у каждого ориентира рабочий хотспот на карте.
- **Зависит от:** Phase 5, Phase 6; решение по источнику арта (см. «Открытые вопросы» ниже)

### Phase 12 — Hardening & store readiness

Полный `flutter test` + `integration_test` + `flutter analyze` зелёные,
реальный прогон производительности на 60 fps на среднем железе, строки
разрешений на местах (`NSHealthShareUsageDescription` на iOS, записи Health
Connect на Android), подготовка карточек в сторах. Монетизации нет нигде —
ни IAP, ни paywalls, ни premium-квестов (§11).

- **Модули:** `ios/Runner/Info.plist`; `android/app/src/main/AndroidManifest.xml`
- **Готово, когда:** релизная сборка ставится и работает офлайн от начала до конца; полный квест Троя → Итака демонстрируется целиком.
- **Зависит от:** всё выше

## Открытые вопросы

Блокируют не весь план, а конкретные фазы — решить до входа в них, не после.

- **Источник арта** для слоёв параллакса и карт квестов — не выбран (§9.1).
  Блокирует визуальную половину Phase 11; нарративная/данные-половина может
  идти на плейсхолдерах.
- **Метод авторизации** для Phase 8 — CLAUDE.md фиксирует Firebase Auth как
  слой, но не метод. Анонимная авторизация — самый низкофрикционный вариант
  для приложения без монетизации; стоит подтвердить до написания Security
  Rules, форма правил зависит от этого.
- **Название собственного фэнтези-мира** — открыто (§14), не блокирует стек
  и Phase 11 (первый квест каталога закрыт «Одиссеей»), но нужно до того, как
  в каталог войдёт второй, не-public-domain квест.
- **Плотность нарративных строк** (`NarrativeBeat`) на квест — открыто (§14),
  влияет на объём текста, который реально нужен в Phase 11.
